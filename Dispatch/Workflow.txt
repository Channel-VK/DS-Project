WHAT GOES WHERE
===================================================================

dispatch.h (the "promise" - what exists, no actual logic)
---------------------------------------------------------
  - #ifndef / #define / #endif header guard
  - #include "graph.h"  (you need Graph/Route structs - get a copy
    of this file from Person A, or the shared Contract doc)
  - struct Buggy
  - struct Request
  - struct AssignmentResult
  - function declarations (signature only, no code):
      Buggy* load_fleet(const char* buggies_path, int* count_out);
      Request* load_requests(const char* requests_path, int* count_out);
      double compute_priority(Request* r, double urgency_weight,
                               double aging_weight, int current_time);
      AssignmentResult run_dispatch_tick(Buggy* fleet, int fleet_count,
                                          Request* pending, int pending_count,
                                          Graph* g, int current_time,
                                          double urgency_weight,
                                          double aging_weight);

dispatch.c (the actual code)
---------------------------------------------------------
  - #include "dispatch.h" at the top
  - #include "cJSON.h"
  - The REAL implementation of every function declared above
  - This is where your priority formula and assignment logic live
  - Calls dijkstra() from graph.h - but you don't write dijkstra()
    yourself, you just CALL it

stub_graph.c (fake routing, just so you can test without Person A)
---------------------------------------------------------
  - #include "graph.h"
  - A FAKE version of dijkstra() that returns made-up but reasonable
    numbers, just so your code compiles and runs
  - This file gets swapped out for Person A's REAL graph.c later -
    you don't need to delete it, just stop including it once the
    real one is ready

test_dispatch.c (just for you, to check your own work)
---------------------------------------------------------
  - Has its own main() function
  - #include "dispatch.h"
  - Loads fleet/requests, tests compute_priority() and
    run_dispatch_tick(), prints results
  - You compile and run THIS alone while developing

===================================================================
SIMPLE WORKFLOW, STEP BY STEP
===================================================================

1. Get a copy of graph.h from Person A (just the header, you don't
   need their .c file yet) so you know the Graph/Route struct shapes.

2. Write the struct definitions in dispatch.h first (Buggy, Request,
   AssignmentResult).

3. Write stub_graph.c with a fake dijkstra() - this unblocks you
   immediately, you don't have to wait for Person A at all.

4. Write load_fleet() and load_requests() in dispatch.c:
     - read the JSON files using cJSON
     - loop through each entry, fill structs
     - IMPORTANT: convert the "status" STRING ("AVAILABLE" /
       "NOT_AVAILABLE") into an INT (1 / 0) while loading - don't
       keep it as a string anywhere else in your code

5. Write compute_priority() in dispatch.c:
     - implement the formula:
       priority = (urgency_weight x urgency)
                + (aging_weight x (current_time - request_time))

6. Write run_dispatch_tick() in dispatch.c:
     - find the pending request with the highest priority
     - loop through buggies, keep only AVAILABLE ones with enough
       capacity
     - call dijkstra() (your stub for now) on each candidate buggy
       to get its distance to the pickup point
     - pick the buggy with the shortest time
     - mark it NOT_AVAILABLE, return the AssignmentResult

7. Write test_dispatch.c to test it:
     - test compute_priority() against hand-calculated values
     - test the "starvation" scenario (old low-urgency request
       should eventually win against new high-urgency ones)
     - test capacity limits and "no buggy available" cases

8. Compile and run JUST your module on its own:
     gcc dispatch.c stub_graph.c test_dispatch.c cJSON.c -o test_dispatch
     ./test_dispatch

9. Once it works, clean up, compile with warnings on:
     gcc -Wall -Wextra dispatch.c stub_graph.c test_dispatch.c cJSON.c -o test_dispatch

10. Write a few sentences explaining your approach (for the report)
    and hand off dispatch.h + dispatch.c to the Coordinator.
    (Your stub_graph.c and test_dispatch.c do NOT go into the final
    combined program - they were just for your own testing.)


===================================================================
QUICK REFERENCE - WHEN TO USE .h vs .c
===================================================================

  .h file  = WHAT exists (struct shapes, function names/signatures)
             Think of it like a table of contents or a menu.

  .c file  = HOW it actually works (the real code inside functions)
             Think of it like the kitchen actually cooking the food.

  You #include "graph.h" because you need to know what a Graph/
  Route LOOKS LIKE and what dijkstra() is CALLED - you don't need
  to see how Dijkstra's algorithm is actually implemented inside.
