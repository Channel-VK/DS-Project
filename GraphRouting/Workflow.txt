===================================================================
WHAT GOES WHERE
===================================================================

graph.h (the "promise" - what exists, no actual logic)
---------------------------------------------------------
  - #ifndef / #define / #endif header guard at the top and bottom
    (prevents the file being included twice by mistake)
  - struct Node
  - struct Edge
  - struct Graph
  - struct Route
  - function declarations (just the signature, ending in semicolon,
    NO curly braces, NO code inside):
      Graph* load_graph(const char* nodes_path, const char* edges_path);
      Route* dijkstra(Graph* g, int from_id, int to_id);
      void free_graph(Graph* g);
      void free_route(Route* r);

graph.c (the actual code)
---------------------------------------------------------
  - #include "graph.h" at the top
  - #include "../lib/cJSON.h"   <- the shared JSON library
  - The REAL implementation of every function declared in graph.h
  - This is where Dijkstra's algorithm actually lives

test_graph.c (just for you, to check your own work)
---------------------------------------------------------
  - Has its own main() function
  - #include "graph.h"
  - Loads the graph, runs a few dijkstra() calls, prints results
  - You compile and run THIS alone while developing, it never goes
    into the final combined program

LIBRARIES YOU NEED (ALREADY PROVIDED - READ THIS CAREFULLY)

cJSON is ALREADY in the repo at lib/cJSON.h and lib/cJSON.c.
You do NOT need to download anything yourself.

RULES:
  1. NEVER edit anything inside lib/. If something about cJSON
     seems broken, the bug is almost always in how YOU are using
     it, not the library itself. Ask the Coordinator if you're
     genuinely stuck.

  2. Just pull the latest repo (git pull) and lib/ will already be
     there - nothing to set up.

  3. Include it in your graph.c like this (note the "../" since
     your folder is one level below the project root, same level
     as lib/):

       #include "../lib/cJSON.h"

  4. When compiling on your own, include cJSON.c in the compile
     command (see "How to compile" below).


===================================================================
SIMPLE WORKFLOW, STEP BY STEP
===================================================================

1. git pull to get the latest repo, confirm you see lib/cJSON.h
   and lib/cJSON.c already there.

2. Write the struct definitions in graph.h first. Get these right
   before writing any logic - everything else depends on them.

3. Write load_graph() in graph.c:
     - open/read campus_nodes.json using cJSON
     - loop through the "nodes" array, fill a Node struct for each
     - open/read campus_edges.json the same way, fill Edge structs
     - put them all into one Graph struct, return a pointer to it

4. Write dijkstra() in graph.c:
     - build an adjacency list from the Graph's edges (for each
       node, know which other nodes it directly connects to)
     - remember to check "bidirectional" - if true, connect both
       ways, if false, only one way
     - run the standard Dijkstra algorithm using a priority queue
       (or even a simple "find smallest unvisited" loop if a real
       priority queue feels too complex for now - correctness
       first, speed later)
     - build and return a Route struct with the path found

5. Write test_graph.c to test it:
     - test on 3-4 pairs of nodes you can verify by hand

6. Compile and run JUST your module on its own:
     gcc graph.c test_graph.c ../lib/cJSON.c -o test_graph
     ./test_graph

7. Once it works, clean up your code, make sure it compiles with
   no warnings:
     gcc -Wall -Wextra graph.c test_graph.c ../lib/cJSON.c -o test_graph

8. Write a few sentences explaining your approach (for the report)
   and hand off graph.h + graph.c to the Coordinator.
   (You do NOT hand off lib/ - it's already shared, Coordinator
   already has it.)


===================================================================
QUICK REFERENCE - WHEN TO USE .h vs .c
===================================================================

  .h file  = WHAT exists (struct shapes, function names/signatures)
             Think of it like a table of contents or a menu.

  .c file  = HOW it actually works (the real code inside functions)
             Think of it like the kitchen actually cooking the food.

  Other files include your .h file to know WHAT functions are
  available to call, without needing to see HOW you wrote them.
